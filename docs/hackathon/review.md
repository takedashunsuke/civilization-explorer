## 0. いまの結論（先に読む）

第1回は「人間を支援する AI」を考えていた。  
第2回は次の一文に寄せる。

**AI 文明を実験場として、人間社会の根本的な問い（格差・権力・幸福・少数派など）を探索する社会シミュレーション。**

| 軸 | 第1回寄り | 第2回（本リポジトリ） |
|----|-----------|----------------------|
| AI の役割 | 人間の判断を助ける道具 | 社会を形成する主体 |
| 人間の役割 | 助言の受け手 | 条件を変え、創発を観測する実験者 |
| 評価との関係 | 評価軸から外れやすかった | マルチエージェント・創発・人工社会に沿う |
| 自分らしさ | 認知バイアス・意思決定支援 | 文明・制度・格差・幸福の問いを組み込む |

プロダクト名は **Civilization Explorer**。実装の正は FeatureSpec / Architecture。

## 1. 背景

AUTOMATA Lab（Singulab）の「LLM マルチエージェントによる社会シミュレーション」ハッカソンについて、第1回を振り返り、第2回のテーマを再検討した。

目的は「受賞だけ」ではない。**今後数年取り組める研究・事業テーマ**を見つけることでもある。

---

## 2. 第1回ハッカソン

### 2.1 応募テーマ

当時考えていた軸:

* 人間の認知バイアス
* リスク認識の補正
* 意思決定支援

発想の骨格は「客観的リスク × 主観的リスク × 認知バイアス × AI 助言」で、

**「人間がより良い判断を行うための AI」＝ AI は人間を支援する存在**

だった。

### 2.2 当時の認識

「LLM エージェントを使う」こと自体に意識が向き、マルチエージェントや社会創発の理解は浅かった。  
AI エージェント＝便利なツール、という認識が強かった。

---

## 3. 第1回の学び（評価軸とのギャップ）

### 3.1 受賞作品の共通点

例:

* LLM マルチエージェントによる月面探査シミュレーション
* 戦争シミュレーション
* 制度設計シミュレーション
* Project Gaara

共通していたのは、

**AI エージェント自身が社会を形成し、相互作用によって創発を生み出す**

こと。人間支援 AI ではなく、**AI 社会そのものを観察する**方向だった。

### 3.2 主催者のテーマ（募集の読み直し）

趣旨は次に近い。

> LLM ベースの AI エージェントに「世界の法則」のみを与え、自律的な意思決定から生まれる社会的創発を観測する

評価の中心:

* AI エージェント
* 相互作用
* 創発
* 人工社会
* 世界モデル

であって、便利ツールや AI アシスタントではない。

受賞後の視野として GitHub 公開・AI コードレビュー・継続研究・論文化も言及されており、**プロダクト開発より人工社会研究**の色が強い。

### 3.3 反省

落選理由は実装不足だけではない。  
**テーマそのものが評価軸から外れていた**可能性が高い。

| 自分（第1回） | ハッカソン |
|---------------|------------|
| 人間の意思決定 | AI 社会 |
| 支援・助言 | 創発・相互作用 |

ここが本質的なズレだった。

## 4. 興味の再配置

### 4.1 当初の違和感

受賞作品にも最初はあまり興味を持てなかった。  
興味の中心がもともと **人間・社会制度・意思決定・バイアス・歴史・文明・幸福** にあり、AI 文明そのものには惹かれにくかったため。

### 4.2 転換点

整理の結果、立場を次に置いた。

**AI 文明を研究したいのではなく、AI 文明を使って人間社会を理解したい。**

AI は目的ではなく **実験環境** である。

例: 「格差」は現実社会では比較実験しにくいが、AI 文明なら条件を変えて何度も生成し、格差・富・権力・制度・幸福を変数にできる。

### 4.3 いま興味がある問い

#### 格差

* 格差は自然発生するのか
* 格差がない社会は成立するのか
* 格差は必要悪なのか

#### 権力

* 富が権力を生むのか
* 必ず支配者は現れるのか
* リーダーは自然発生するのか

#### 能力差

* 能力差があっても公平な社会は作れるか
* 全員同じ能力なら幸福なのか
* 優秀な人だけが文明を発展させるのか

#### 幸福

* 犯罪や事故による悲しみがない社会は成立するか
* タブーがなくても幸福な文明は存在するか
* 自由と幸福は両立するか

#### 少数派（特に強い関心）

> 異常値（少数派・逸脱者）に優しい文明は生まれるのか

人間社会でも重要な問いだと捉えている。

### 4.4 文明の「大量生成」という発想

一回きりの文明制作ではなく、**多数回生成して共通点を抽出する**方向に興味がある。

* 幸福な文明 / 長寿命文明 / 格差の少ない文明 / イノベーションが起きる文明 などを抽出し分析する
* AI が答えを出すのではなく、**大量の社会実験を行い、人間が学ぶ**

ただしこれは **長期ビジョン** である。ハッカソン MVP では「条件を変え → 創発を観測 → 蓄積・再実行できる」ループを成立させることを先にする（何千回のバッチ分析 UI は発展機能）。

### 4.5 重要な前提

シミュレーションは **真理の証明ではない**。

**ある条件を与えたとき、どのような社会が創発するか** を観察する仮説探索の道具である。  
「格差が必要」などを証明するものではない。

## 5. 第2回への設計方針

### 5.1 やること

* AI エージェントを主役にする
* 世界のルール（法則）だけを設計する
* 文明がどう創発するかを観察する
* 社会科学的な問い（格差・権力・幸福・少数派など）を設定する
* 同条件再実行・結果の蓄積を可能にし、将来の大量実行につなげる
* 結果を 2D マップと Event / メトリクスで可視化する

### 5.2 やらないこと

* AI チャットボットを作る
* 人間を直接支援する AI を作る
* 単なる業務効率化ツール
* AI を便利な UI として使うだけ
* 正解を導く AI を作る

### 5.3 Civilization Explorer への落とし込み

| review の意図 | リポジトリでの表現 |
|---------------|-------------------|
| AI が社会を形成 | LLM Agent が意思決定、ルール層が結果を確定 |
| 人間は実験者 | 初期条件・制度のみ変更（PrimeVue） |
| 創発を観測 | 2D マップ + タイムライン（地球・本格 3D なし） |
| 仮説探索 | seed・パラメータ保存、同条件再実行 |
| 大量生成ビジョン | MVP はループ成立。相図・大規模比較 UI は発展機能 |
| 評価軸に沿う | マルチエージェント・創発・人工社会をデモの中心に置く |

* 文明は何を目的に進化するのか
* 少数派に優しい社会はどのような条件で成立するのか
* 何千回もの文明シミュレーションで、繰り返し現れる制度や価値観はあるのか
