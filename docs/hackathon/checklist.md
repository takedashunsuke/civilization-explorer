# 当日チェックリスト

> ステータス: 下書き

## 事前（発表の数時間前）

* [ ] `supabase start` が成功する
* [ ] Backend（FastAPI）が起動し、`/docs` が開く
* [ ] Frontend（Nuxt）が開く
* [ ] LLM（Ollama または外部 API）が応答する
* [ ] デモ用シナリオ（seed・パラメータ）を 1 本決めておく
* [ ] 発表で使う問いを 1 つに絞る（格差 / 権力 / 少数派 など）
* [ ] ピッチが「支援 AI」になっていないか [overview.md](./overview.md) で確認
* [ ] 録画バックアップを用意する（ライブ失敗用）
* [ ] 画面共有解像度・フォントサイズを確認する

## 起動順（ローカル）

1. Docker / Supabase
2. Backend
3. LLM（Ollama など）
4. Frontend
5. ブラウザでメイン画面を開く

（コマンドの確定版は実装後に `docs/guides/setup.md` / `demo.md` へ書く）

## 障害時

| 症状 | 対処 |
|------|------|
| LLM が遅い / 落ちる | スタブ意思決定 or 録画に切替 |
| DB 接続失敗 | `supabase status` → 再 `start` |
| 画面が更新されない | 手動 tick / ポーリング確認 |
| 全体が不安定 | 録画デモへ即切替 |

## 発表直前

* [ ] 余計なタブを閉じる
* [ ] API キーや `.env` が画面に映らない
* [ ] デモ用データが初期状態に戻っている
