**第2回は「対照実験装置として成立した」ことが評価され、入賞した。**  
講評後は同一ショック × 社会応答でレジリエンスを測った。1b では社会差が出る。8B 決定では共同が突出し差が消える。人数を 1 に落とすと争いは戻るが生存差は薄い。初期富の幅を乗せる（`run3-005`）と生存のスプレッドは戻る。大きいモデル＝回復ではない。メタ安全保障の一文は README / overview に掲載済み。

| 今回（入賞） | 次回（修正の軸） |
|--------------|------------------|
| 同じ人間 × 異なる環境 → 歴史が分岐するか | 同じ危機 × 異なる社会応答 → 回復／崩壊の分岐条件 |

## 2. 藤井学長からの講評

**藤井学長（デジタルハリウッド大学）**

同一の 5,000 人を環境だけ変えた 4 世界に置き、200 年 × 10 seed を CLI で完走させ、生ログと横断サマリーまで整備した工学的な完成度は評価できます。「争いは再現しにくい」と正直に書いた点も好印象です。ただ、得られた差は環境ノブがそのまま指標に現れたものに留まり、人口動態は 4 世界で同一、1b モデルの地域観測は意味を成しておらず、「メタ安全保障」との接続も語られていません。次は災害・資源の変動に対して社会が回復するか崩壊するかの分岐条件（レジリエンス）を問いの中心に据え、より大きなモデルで住民の意思決定を担わせると、テーマにも結果にも厚みが出るはずです。

### 4.2 今後の実証方針

`run3-003` までで、**モデルを大きくすると行動は動くが、協力に寄りすぎて社会差が消える**ことが分かった。以降の実証は「もっと大きなモデル」ではなく、**差が残る条件を一つずつ切り分ける**。`run3-005` で初期富の幅を乗せると、8B n=1 でも生存のスプレッドは戻った。年齢死とショック帰属死はコードで分離済み。次は 10 seed ではなく、UI の同一 ID 比較。

**固定する条件**

* 系列は `run3`。実験は `run3-005` まで。これ以上の seed / モデル上げはしない（v1 の `run-015` は使わない）
* ショック計画は seed+stage から事前生成し、4 variant に同じ列を載せる
* 比較の正は同一 seed・同一計画の A/B（いまは seed 42、計画 42 件）
* 入賞時 `run-001`〜`010` は上書きしない。environment の再測は `--series run2`

**主指標（この順で読む）**

1. `pop_retention_ratio`（期末 / ショック前）。総人口の読み
2. `shock_mortality_ratio`（ショック帰属死 / ショック前人口）と `shock_death_share`。ラベルはこちら
3. ショック後の協力比と、共同・争いの件数
4. `regime_break`・資源の期末値
5. 4 variant のスプレッド（差が消えたら、その実験は「効きすぎ」と書く）

**次に足してよい実験**

切り分けは `run3-005`（初期富の幅）まで済。生存のスプレッドは戻ったが、200 年のラベルは年齢死で潰れていた。年齢死とショック帰属死の分離はコード済（stub パイロットで確認）。これ以上の 10 seed / 観測 8B はしない。次は UI の同一 ID 比較。

**コード側で先に直してよいこと（実験なし）**

* ~~比較表の保持率を小数 3 桁にする~~（済。`f3`。run3 再生成済み）
* ~~同一 ID のクロスワールド比較をサマリーの固定枠にする~~（済。初期名簿のみ。run3 は 1 世界生存が stub 2 / 8B 15、2 世界以上は 0）
* ~~`inequality` を初期富に乗せる~~（済。`run3-005` で 1 seed。004 には未適用）
* ~~年齢死とショック帰属死を分ける~~（済。年次死を競合リスクで振り分け。ラベルは `shock_mortality_ratio`。stub 10 turn で lush=stressed / lean=collapsed）

**やらない（当面）**

* さらに大きい決定モデル、観測まで 8B
* 全 5,000 人を毎ターン個別 LLM
* 「メタ安全保障」を別プロダクトとして実装し直す
* 入賞時 environment 10 run のやり直し

## 5. 具体的な実装方針

### 5.1 Phase A — 環境が人口に届く（必須）— **実装済（2026-09）**

**目的:** 講評の「人口が同一」を解消し、レジリエンスの土台を作る。

| 変更 | 方針 | 主な箇所 | 状態 |
|------|------|----------|------|
| 死亡 | 地域 `resource_pool` が低い／`shock_stress` で死亡確率を上げる | `engine.py` `_yearly_death_chance` / `apply_deaths` | ✅ |
| 災害致死 | 大規模災害でサンプル致死。`disaster_frequency` が高いほど率・幅が上がる | `engine.py` `apply_disasters`、`shocks.py` | ✅ |
| 出生 | 資源不足・shock で出生を抑える | `engine.py` `apply_births` | ✅ |
| 資源枯渇スパイラル | regen を scarcity・幸福・人口・制度に依存 | tick 末尾の regen | ✅ |

**パイロット:** `scripts/pilot_phase_a.py`（seed=42・10 turn・stub）  
例: lush 867 / lean 308 / volatile 672 / balanced 852（alive）。資源も lush ≫ lean。

**受け入れ条件**

* [x] 同一 seed で volatile の生存人口が lush より低い
* [x] lean は資源が lush より低い（回復しにくい）
* [x] 4 世界の alive スプレッドが十分（パイロット ≥ 30）

**注意:** 差を出すためにノブを極端にしすぎると「環境ノブの写像」批判が再発する。  
差の**経路**（死・出生・回復失敗）をログに残し、「なぜ分かれたか」を説明できること。

### 5.2 Phase B — レジリエンス指標 — **実装済（2026-09）**

**目的:** 「回復か崩壊か」を数値で語れるようにする。

| 指標 | 定義 | 状態 |
|------|------|------|
| `shock_count` | 災害イベント数 | ✅ |
| `disaster_deaths` | `death_disaster` 件数（災害直死） | ✅ |
| `age_deaths` | `death_age` + `death_hardship` | ✅ |
| `shock_attributed_deaths` | 災害直死 + `death_shock` + `death_scarcity` | ✅ |
| `shock_death_share` | ショック帰属死 / 全死亡 | ✅ |
| `shock_mortality_ratio` | ショック帰属死 / ショック前人口。ラベルの主指標 | ✅ |
| `pop_trough` | ショック以降の人口最下点 | ✅ |
| `pop_recovery_ratio` | `(期末 − 最下点) / (ショック前 − 最下点)`（単調減少では 0 付近） | ✅ |
| `pop_retention_ratio` | `期末 / ショック前`（総人口。年齢死を含む） | ✅ |
| `resource_recovery_halftime` | 50% を割ったあと戻るターン（割っていなければ null） | ✅ |
| `regime_break` | 権威が閾値割れ／大幅低下、または anarchy への転換 | ✅ |
| `coop_vs_conflict_post_shock` | ショック後の協力 / (協力+争い) | ✅ |
| `resilience_label` | `recovered`（帰属死 < 8% かつ制度維持） / `collapsed`（≥ 18%） / `stressed` | ✅ |

実装:

- パイロット表示（`scripts/pilot_phase_a.py`）

### 5.3 Phase C — 実験プロトコルの進化 — **実装済（2026-09）**

**現行（残す）:** 同一人間 × 環境ノブ差（`--protocol environment`）  
→ 「環境は効くか」のベースライン。

**追加（講評対応の主プロトコル）:** `--protocol resilience`


**注意（2026-09-19）:** resilience は `generate_shock_plan` で **(turn, 地域, 種類)** を seed から先に作る。適用乱数はイベントごとに独立なので、死亡の差が後続ショックをずらさない。疫病発生は `trade_openness` を見ない（計画時は 0.5 固定）。社会は応答（誰が死ぬか・資源が戻るか）だけ変える。environment プロトコルは従来どおり確率的。

| `fracture` | 無政府・分断 |

## 6. 「メタ安全保障」との接続（語り）

コードに同名モジュールはまだない。接続は**問いのフレーミング**で行う。README / [overview.md](./overview.md) に 2026-09-21 掲載済み。

掲載した一文:

> 国家や制度が前提の安全保障ではなく、**環境ショックの下で社会が協力・制度・指導を再編成できるか**を人工世界で測る。これが Civilization Explorer におけるメタ安全保障の実験的定義である。

指標との対応: `pop_retention_ratio`・`regime_break`・ショック後の協力比が、その操作的定義になる。`pop_recovery_ratio` と recovered ラベルは参考（単調減少では 0 になりやすい）。

`run3-003` の読み: 8B は協力を増やしたが、再編成の**差**は消えた。`run3-005` で初期富の幅を乗せると生存のスプレッドは戻るが、格差が大きいほど死ぬ、ではない。メタ安全保障は「協力が多いこと」ではなく「社会ごとに応答が分かれること」で測る。大きいモデル＝回復、ではない。以降の実験は §4.2 に従う。
